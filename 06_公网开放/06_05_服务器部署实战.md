# 服务器部署实战

本章将带你完成一个完整的应用部署流程。从购买服务器开始，到配置环境、部署应用、配置域名，让我们把应用真正发布到公网上。

---

## 一、服务器环境初始化

### 1. 连接到服务器

首先，使用SSH连接到你的云服务器：

```bash
ssh root@你的服务器IP
```

如果是Windows用户，可以使用PowerShell或PuTTY。

### 2. 创建非root用户

出于安全考虑，不建议直接使用root用户运行应用：

```bash
# 创建新用户
adduser deploy

# 添加到sudo组（需要时可以使用sudo）
usermod -aG sudo deploy

# 切换到新用户
su - deploy
```

### 3. 更新系统

```bash
# 更新软件包列表
sudo apt-get update

# 升级已安装的软件
sudo apt-get upgrade -y
```

### 4. 安装Docker

参考前一章内容，安装Docker和Docker Compose：

```bash
# 安装Docker
curl -fsSL https://get.docker.com | sh

# 启动Docker
sudo systemctl start docker
sudo systemctl enable docker

# 将当前用户添加到docker组
sudo usermod -aG docker $USER

# 安装Docker Compose
sudo curl -L "https://github.com/docker/compose/releases/download/v2.23.0/docker-compose-$(uname -s)-$(uname -m)" -o /usr/local/bin/docker-compose
sudo chmod +x /usr/local/bin/docker-compose
```

### 5. 配置防火墙

```bash
# 查看防火墙状态
sudo ufw status

# 启用防火墙
sudo ufw enable

# 允许SSH连接（重要！否则可能断开连接）
sudo ufw allow 22/tcp

# 允许HTTP和HTTPS
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp

# 查看规则
sudo ufw status verbose
```

## 二、应用部署流程

### 1. 准备项目文件

将你的项目上传到服务器。有多种方式：

**方式一：使用Git**

```bash
# 安装Git
sudo apt-get install git -y

# 克隆仓库
git clone https://github.com/yourusername/yourproject.git

# 进入项目目录
cd yourproject
```

**方式二：使用SCP**

```bash
# 从本地上传文件
scp -r ./yourproject root@服务器IP:/home/deploy/
```

**方式三：使用SFTP**

使用FileZilla等工具通过SFTP协议上传文件。

### 2. 配置环境变量

创建`.env`文件（不要提交到Git！）：

```bash
# 进入项目目录
cd yourproject
nano .env
```

添加必要的环境变量：
```
# 数据库配置
DATABASE_URL=postgresql://user:password@db:5432/mydb

# Redis配置
REDIS_URL=redis://cache:6379

# 密钥
SECRET_KEY=your-very-long-random-secret-key

# 开放AI API（如果使用）
OPENAI_API_KEY=sk-xxxxx
```

### 3. 启动应用

使用Docker Compose启动所有服务：

```bash
# 启动服务
docker-compose up -d

# 查看服务状态
docker-compose ps

# 查看日志
docker-compose logs -f
```

如果一切正常，你的应用现在应该已经运行在容器中了。

## 三、Nginx反向代理配置

### 1. 为什么需要Nginx

Nginx作为反向代理的好处：
- **负载均衡**：分担多实例的请求
- **SSL终结**：处理HTTPS加密
- **静态文件服务**：高效服务图片、CSS、JS
- **缓存加速**：缓存常用资源
- **安全防护**：隐藏真实后端服务

### 2. Nginx配置文件

创建Nginx配置文件：

```bash
sudo nano /etc/nginx/sites-available/yourdomain.com
```

配置示例（HTTP）：
```nginx
server {
    listen 80;
    server_name yourdomain.com www.yourdomain.com;

    location / {
        proxy_pass http://localhost:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }

    # 静态文件（如果前端是分离的）
    location /static/ {
        alias /path/to/static/files/;
    }

    location /media/ {
        alias /path/to/media/files/;
    }
}
```

### 3. 启用配置

```bash
# 创建软链接
sudo ln -s /etc/nginx/sites-available/yourdomain.com /etc/nginx/sites-enabled/

# 测试配置
sudo nginx -t

# 重载Nginx
sudo systemctl reload nginx
```

## 四、HTTPS证书配置

### 1. 为什么需要HTTPS

- **数据加密**：防止数据被窃听
- **身份验证**：证明网站真实性
- **SEO优化**：搜索引擎偏好HTTPS
- **浏览器信任**：避免"不安全"警告

### 2. 使用Let's Encrypt免费证书

安装Certbot：
```bash
sudo apt-get install certbot python3-certbot-nginx -y
```

获取证书：
```bash
sudo certbot --nginx -d yourdomain.com -d www.yourdomain.com
```

按照提示输入邮箱并同意服务条款。

### 3. 自动续期

Let's Encrypt证书有效期为90天，Certbot会自动配置续期任务。验证：
```bash
sudo certbot renew --dry-run
```

### 4. 配置HTTPS（Nginx完整示例）

```nginx
server {
    listen 443 ssl http2;
    server_name yourdomain.com www.yourdomain.com;

    # 证书路径（Certbot自动配置）
    ssl_certificate /etc/letsencrypt/live yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live yourdomain.com/privkey.pem;

    # SSL配置
    ssl_session_timeout 1d;
    ssl_session_cache shared:SSL:50m;
    ssl_session_tickets off;

    # 现代加密配置
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256;
    ssl_prefer_server_ciphers off;

    location / {
        proxy_pass http://localhost:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }
}

# HTTP自动跳转到HTTPS
server {
    listen 80;
    server_name yourdomain.com www.yourdomain.com;
    return 301 https://$host$request_uri;
}
```

## 五、域名解析与绑定

### 1. 添加域名解析

登录你的域名注册商后台，添加DNS解析记录：

| 记录类型 | 主机记录 | 记录值 |
|---------|---------|--------|
| A | @ | 你的服务器IP |
| A | www | 你的服务器IP |

**等待生效**：DNS解析通常需要几分钟到几小时生效。

### 2. 验证域名解析

```bash
# 使用ping命令验证
ping yourdomain.com

# 使用nslookup
nslookup yourdomain.com
```

## 六、部署后的验证与调试

### 1. 检查服务状态

```bash
# Docker服务状态
docker-compose ps

# Nginx状态
sudo systemctl status nginx

# 查看端口监听
sudo netstat -tlnp | grep -E ':(80|443|8000)'
```

### 2. 查看日志

```bash
# 应用日志
docker-compose logs -f

# Nginx错误日志
sudo tail -f /var/log/nginx/error.log

# Nginx访问日志
sudo tail -f /var/log/nginx/access.log
```

### 3. 常见问题排查

**问题：无法访问网站**

排查步骤：
1. 检查服务器防火墙是否开放80/443端口
2. 检查云服务商安全组是否开放端口
3. 检查Nginx是否运行
4. 检查Docker容器是否运行

**问题：网站显示502错误**

排查步骤：
1. 检查后端服务是否正常运行
2. 检查Nginx配置的proxy_pass是否正确
3. 检查容器日志

**问题：证书获取失败**

排查步骤：
1. 确认域名已正确解析
2. 确认防火墙开放80端口
3. 确认域名指向正确的服务器IP

## 七、部署后的维护

### 1. 定期备份

```bash
# 备份数据库（示例）
docker-compose exec db pg_dump -U user mydb > backup_$(date +%Y%m%d).sql
```

### 2. 监控

可以使用以下工具监控服务器状态：
- **htop**：查看CPU、内存使用
- **docker stats**：查看容器资源使用
- **Uptime Robot**：监控网站可用性

### 3. 日志管理

配置日志轮转，避免日志文件过大：

```bash
sudo nano /etc/logrotate.d/nginx
```
